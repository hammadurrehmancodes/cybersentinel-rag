# CyberSentinel Security Copilot

CyberSentinel is a local, privacy-conscious cybersecurity assistant built with FastAPI, Chroma, and sentence-transformers. It analyzes firewall and authentication logs, retrieves relevant incident-response guidance from a local knowledge base, and produces plain-English incident summaries, severity assessments, response playbooks, and recommendations.

The project is designed for local development and demonstration use. It can work offline for most of its knowledge base and uses Groq for LLM-based response generation when an API key is available.

## Features

- Analyze raw firewall, UFW, iptables, and SSH authentication logs
- Detect suspicious activity patterns and extract important IPs and ports
- Retrieve guidance from a local vector database built from NIST, MITRE ATT&CK, and custom log patterns
- Generate incident response playbooks and recommendations
- Provide an API for integration with web or mobile clients
- Export analysis results as PDF reports

## Project Structure

- main.py: FastAPI application entry point
- copilot/routes.py: API routes and request/response models
- copilot/security_copilot.py: core retrieval and LLM orchestration logic
- copilot/log_analyzer.py: log parsing and event extraction
- copilot/report_generator.py: PDF report generation
- seed_db.py: builds the local Chroma knowledge base
- data/: source knowledge files used to build the vector database
- chroma_storage/: local vector database files generated by seed_db.py

## Requirements

- Python 3.10 or newer
- pip
- A Groq API key (recommended for full functionality)

## Quick Start

1. Create and activate a virtual environment

```bash
python3 -m venv venv
source venv/bin/activate
```

2. Install dependencies

```bash
pip install -r requirements.txt
```

3. Create your environment file

```bash
cp .env.example .env
```

Edit the .env file and set your values.

4. Build the local knowledge base

```bash
python seed_db.py
```

This creates the local vector database inside the chroma_storage directory.

5. Start the API server

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8001
```

The API will be available at:

- http://127.0.0.1:8001/docs
- http://127.0.0.1:8001/

## Environment Variables

Create a .env file with the following variables:

```env
GROQ_API_KEY=your_groq_api_key_here
GROQ_MODEL=llama-3.3-70b-versatile
CHROMA_PATH=./chroma_storage
EMBEDDING_MODEL=all-MiniLM-L6-v2
```

If GROQ_API_KEY is not set, the app will fail when it tries to generate AI responses. The knowledge base can still be built locally.

## API Endpoints

### Health Check

```bash
curl http://127.0.0.1:8001/api/copilot/health
```

### Analyze Logs

```bash
curl -X POST http://127.0.0.1:8001/api/copilot/analyze-logs \
  -H "Content-Type: application/json" \
  -d '{
    "log_text": "Jan 15 03:22:11 server kernel: [UFW BLOCK] IN=eth0 SRC=185.220.101.45 DST=10.0.0.1 DPT=22"
  }'
```

### Ask a Question

```bash
curl -X POST http://127.0.0.1:8001/api/copilot/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is an SSH brute force attack and what should I do?"}'
```

### Investigate an IP

```bash
curl -X POST http://127.0.0.1:8001/api/copilot/investigate-ip \
  -H "Content-Type: application/json" \
  -d '{
    "ip_address": "185.220.101.45",
    "platform_data": {
      "abuseipdb_score": 95,
      "country": "Germany",
      "isp": "Tor Exit Node"
    }
  }'
```

## Knowledge Base Setup

The vector database is built from the files in the data directory. You can refresh it at any time:

```bash
python seed_db.py --reset
```

To skip MITRE ATT&CK data collection and use the local knowledge base only:

```bash
python seed_db.py --skip-mitre
```

## Notes

- The local knowledge base is stored in chroma_storage and is generated by seed_db.py.
- The project uses a local embedding model, so the first run may take a few minutes while dependencies download.
- If you want to use the app fully, make sure you provide a valid Groq API key in the .env file.
